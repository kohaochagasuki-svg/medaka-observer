# めだかラボ — 中央線横断の自動計測（試験版）

高校の探究活動で、水槽5匹のメダカの活動量を比較するための、HTML・CSS・JavaScript製のアプリです。AndroidのChromeを対象にしています。有料API・外部CDN・動画アップロードは使いません。

## できること

- 既存の動画選択、再生・停止・シーク・速度変更、指で動かせる縦／横の中央線を維持。
- 水槽ID、光の照射時間（時間/日）、水温、匹数、明るさ、メモを端末に保存。旧バージョンの記録も復元。
- 縮小映像から動く細長い候補を検出し、移動予測と全体の対応付けで追跡。
- 検出枠全体が判定帯の反対側へ移り、その状態が連続して観測されたら横断候補を記録。縦線は左→右／右→左、横線は上→下／下→上。
- 検出枠・候補ID・短い軌跡・除外範囲・解析時の線を重ね表示。解析後の映像再生でも記録を確認。
- 背景との差・面積・解析範囲・器具などの除外範囲を調整。
- 候補の確認／除外、時刻・方向・メモの修正、見落とした横断の手動追加。
- 独立した手動カウントと、修正前の自動候補数を比較。
- CSV保存（確認状態、修正前の値、観察条件、設定、途中結果と処理範囲を含む）。
- 進捗表示と中断。最初は先頭3分、調整用10秒、長時間用は先頭30分までを選択可能。

**自動結果はすべて「未確認候補」です。確認済みにしたものだけが合計に入ります。候補0件でも横断なしを意味しません。** この方式はメダカ専用の学習済み認識器ではなく、動体検出です。気泡・動く反射を完全には区別できず、透明な尾を含めた全身の位置も保証できません。目視確認と実動画での精度評価が必要です。

## 使う順番

1. 水槽全体を固定カメラで撮影した動画を読み込み、中央線を合わせる。
2. 水槽ID、照射時間、匹数（標準5）を記録する。
3. 「自動計測」の先頭3分を実行する。まず10秒で設定を調整してもよい。
4. 検出枠が魚を囲むか、反射や気泡を拾っていないか確認する。橙の枠は追跡開始中・不確かな状態。
5. 「見直す必要がある区間」から、追跡切れや重なりがあった場面を再生する。候補一覧がない場所にも見落としがあり得る。
6. 候補ごとに「映像へ」から少し前に戻り、全身横断と方向・時刻を確かめて「確認済み」または「除外」にする。必要なら時刻・方向を修正し、見落としを手動追加する。
7. 同じ対象区間を独立に手動でカウントして比較し、CSVを保存する。

確認前の候補をまとめて正確な値にする操作はありません。合計の一致だけでは誤検出と見落としの相殺を見抜けないため、時刻ごとの照合も必要です。5匹の群全体の活動量を扱います。候補IDで個体別の活動量を比較しないでください。

## 保存と省メモリ設計

動画はblob URLで端末内再生し、全量をArrayBufferやbase64にしません。長辺480px以下の1枚をWorkerに送り、完了してから次へ進みます。背景推定は最大9枚のグレースケール画像、追跡中の状態は最大設定匹数（1〜10）です。

追跡の座標記録は10秒ごとにIndexedDBへ書き、全フレームの画像や全座標をメモリにためません。確認時も1区間だけ読み込みます。横断イベントは最大30,000件で停止します。動画のデコーダーやブラウザ側のメモリはこの制限の対象外なので、30分や4K動画の負荷は実機で確認してください。

観察条件と中央線設定はlocalStorageに**直近1件**を保存します。解析結果は再読込では復元しません。追跡座標は今回の確認用にIndexedDBへ一時保存し、動画変更・再解析・終了時に削除を試みます。強制終了で残った記録は翌日以降の起動時に清掃します。入力や動画をサーバーに送る処理はありません。

動画変更・再解析・ページ再読込で確認結果が消えるため、先にCSVを保存してください。中断は再開ではありません。処理済み区間の結果を見直して保存するか、最初から再解析します。画面を閉じたりバックグラウンドに移った場合も中断します。途中結果は全時間の活動量として比較しないでください。

## ソースと確認用ブランチ

リポジトリ：<https://github.com/kohaochagasuki-svg/medaka-observer>

今回のブランチは `codex/medaka-auto-count`、マージ先は `main` です。公開ページのファイルやホスティング設定を直接更新しません。実機確認後にPRをレビューし、マージと公開は別途判断してください。

| ファイル | 内容 |
| --- | --- |
| `index.html`, `styles.css`, `app.js`, `icon.svg` | 観察画面と既存機能 |

| `analysis-worker.js` | フレームごとの解析Worker |
| `analysis-storage.js` | 座標を10秒単位で端末に一時保存 |
| `analysis.js` | 解析進行、中断、重ね表示、結果確認 |
| `docs/architecture.md` | 方式の選定と判定の定義・限界 |

## Pixel 8aで公開せずに試す

[端末内起動の手順](docs/pixel-local-check.md) で、実装ブランチのZIPを取得し、無料のTermuxとPythonで端末内サーバーを起動します。Chromeで `http://127.0.0.1:8000` を開いて確認できます。GitHubのファイル表示やRaw画面は実行ページではありません。

スマホから追加編集する場合はGitHubのファイル編集、またはURLの `github.com` を `github.dev` に変えたWebエディターを使い、作業ブランチにコミットします。必要ならChromeの「PC版サイト」を有効にしてください。

## 開発時のテスト

Node.js 22以降を使用します。

```sh
npm ci
npm run check
```

ブラウザテストにはPython 3、Pillow、ffmpeg、Chromiumが必要です。`MEDAKA_CHROMIUM` で実行ファイルを指定できます（標準 `/usr/bin/chromium`）。これらは開発時のみ必要です。

```sh
npm run test:video
npm run test:browser
```

動画生成はテスト用の3分間の合成動画をローカルに作ります。実際のメダカ動画はリポジトリに含めません。合成動画での成功は実際の魚の検出精度を示しません。確認結果と実動画で調べる項目は [動作確認記録](docs/verification.md) を参照してください。
