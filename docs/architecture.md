# 自動解析の方式と制限

## 選定

Android Chromeでの負荷、無料、外部送信なしを優先し、依存ライブラリやモデルファイルなしの古典的な動体検出を採用した。最初の実用評価向けの試験版であり、メダカ専用の学習済み検出器ではない。学習用のアノテーション済み実動画がない状態で、魚種の識別精度を主張しない。

巨大な汎用物体検出モデルはメダカの小さな像・透明な尾に適合する保証がなく、スマホへのダウンロード、推論メモリ、訓練データ、ライセンスの検証が別途必要になる。OpenCV.js一式を読み込む代わりに、今回必要な演算のみJavaScriptで実装した。実動画で限界を測った後、必要なら小さな専用モデルとの比較を行う。

## フレーム取得・背景差分

- `<video>` は1個。動画ファイルをblob URLで参照し、全量コピーをしない。
- 再生を止め、メディア時刻を順にシークする。デコード完了を確認して長辺480px以下のCanvasへ描画する。1枚のRGBAバッファをWorkerへ転送し、返答を待って次へ進む。シーク待ち、Worker待ちには中断と15秒のタイムアウトがある。
- 最初の最大3秒から9枚だけ採取し、画素ごとの中央値で初期背景を推定する。この間は計数しないが、その後0秒に戻って全対象区間を解析する。背景用9枚は推定後に解放する。
- グレースケール化し、全体の露出差を中央値で補正して背景との差を閾値化する。背景はゆっくり更新する。
- 微小ノイズを近傍画素数で抑え、8近傍の連結成分を取り出す。面積・共分散から求めた細長さ・充填率で候補を絞る。円形の小気泡や静止器具を抑制するが、動く反射・細長い気泡には不十分。
- 解析範囲と最大8個の矩形マスクを指定できる。範囲外は検出しないので、魚が出ると追跡切れになる。
- 大きい照明変化や映像全体の変化は計数せず、追跡をリセットして要確認区間にする。照明条件の異なる動画はそれぞれ新規に背景を推定する。

初期3秒でほぼ動かない魚は背景に取り込まれ得る。停止、透明な魚、背景と同色の魚、水草、カメラの揺れ、反射、照明の点滅では検出が不安定になる。

## 複数候補の追跡

最大設定匹数（標準5、上限10）を保持する。速度予測に対する距離と面積比からコストを作り、Hungarian法で全体の対応付けを求める。移動・面積のゲートを外れる対応は拒否する。3回以上継続した観測を連続追跡状態とする。

複数候補が競合する場合、接近・重なり、観測間隔が空いた場合は不確かとして、横断判定の状態をリセットする。検出を失ったフレームでも横断状態をリセットする。短時間はIDを保持して再対応を試みるが、消失期間の位置を補間して数えない。0.5秒を超える消失で追跡状態を破棄する。IDは映像上の候補の通し番号であり、同一の魚の生体識別ではない。重なり後に入れ替わる可能性も残る。

## 完全横断の操作上の定義

検出枠を全身の近似として使う。中央線の両側に標準1.5%ずつの判定帯を設ける。枠全体が片側にあることを2フレーム以上確認して起点を確立し、判定帯との交差を経て、枠全体が反対側に出たことを2フレーム以上観測した場合に1候補とする。同じ側での継続検出や帯内の往復では増やさない。

出発側を確立できない開始時の個体、追跡切れをまたぐ移動、帯の通過を1枚も観測できなかった高速移動は、横断として推測しない。真の素早い横断を過少計数する場合がある。完全に片側へ出た後、戻って再び完全に横断した場合は逆方向に1候補になる。

尾が検出されない場合や検出枠の欠けはこの定義の誤差要因になる。時刻は反対側で枠全体が観測された最初のサンプルの時刻で、連続時間の厳密な横断瞬間ではない。標準10枚/秒でのサンプリング誤差に加え、検出誤差がある。横線の場合は上下方向として扱う。

## 不確かさと人による確認

- 自動候補はすべて `pending`。手動で確認済みにするまで合計に含めない。
- 検出数・連続追跡数が設定匹数に満たない場合、競合、消失、照明変化などを5秒単位の要確認区間にまとめる。候補0件を正確な0横断と表示しない。
- 全設定数の候補を継続追跡できたフレーム率は、品質の目安であり検出精度・信頼区間ではない。反射が5個検出されても魚とは限らない。
- 原候補の時刻・方向を残し、修正後の値、除外、手動追加をCSVに分けて残す。
- 独立手動カウントとの方向別差・合計絶対誤差率を表示する。合計から適合率・再現率は計算しない。時刻を照合した真陽性・偽陽性・偽陰性の評価は実動画で別途行う。

## メモリ・保存・終了

Workerは背景と作業用TypedArray、最大9枚の背景推定用画像、最大設定匹数の追跡状態だけを保持する。30分分の画像を蓄積しない。座標と状態のみ10秒ごとの区間にまとめてIndexedDBへ保存し、再生時も1区間だけキャッシュする。最大30,000イベントで停止する。CSVは要約行に条件・合計・区間情報を持ち、イベント行ごとに巨大なメタデータを複製しない。

中断はAbortControllerでシーク・Worker待機・背景推定中にも通知する。Worker終了、待機リスナーとタイマー解除、Canvas縮小を行い、処理済みの最後の座標区間を保存して通常の動画操作へ戻す。進捗100%は全対象フレームと最後の座標保存が終わった時だけ。途中CSVには状態と処理済み時間を記録する。

解析結果はページ内の今回の確認用で、再読込での復元はない。動画変更・再解析で以前の記録を削除し、異常終了で残った座標は1日後に清掃する。タブごとの一意なIDを使い、他のタブの記録を消さない。保存容量不足は成功扱いにせず途中結果として報告する。

ブラウザの動画デコーダー・キャッシュのメモリや消費電力をこの設計だけで保証することはできない。精密シークはコーデックによって遅くなる。解析の実時間以下での完了も保証しない。30分の実動画・Pixel実機での負荷、発熱、ブラウザ停止の評価は別途必要。
