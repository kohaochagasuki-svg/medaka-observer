### 合成動画で確認できたこと

`tests/generate-video.py` で生成した180秒、320×180px、10fpsのMP4を使用した。5つの細長い魚相当の像を別々の高さで往復させ、静止器具と移動する小さな円も描いた。既知の横断は左→右30、右→左30の合計60回。

ブラウザで1800枚を順次処理し、60候補を記録した。自動候補はすべて未確認のままで、確認済み合計は初期0。手動の確認・修正・追加・除外が集計とCSVに反映されることを確認した。座標記録は100フレームずつ18区間へ保存された。外部HTTPリクエストやPOSTはなく、localhostへのアプリファイル取得のみだった。

412px幅と1280px幅のスクリーンショットでも表示を確認した。スマホ幅の候補表は表内を横スクロールして確認状態・メモを操作する。Linuxで3分動画の解析は約1〜1.5分だったが、これはPixelの速度や消費電力を示さない。

**合成動画の60/60は、実際のメダカの検出精度ではない。** 合成像は高コントラストで重なりがなく、魚の透明な尾・複雑な反射・奥行きを再現していない。現時点で実動画の適合率・再現率は不明。

## Pixelで最初に試す手順

[端末内起動](pixel-local-check.md) を使い、既存の公開ページを変更せず、実装ブランチをChromeで開く。

1. 短い動画で従来の再生・中央線・条件保存を確認する。
2. 水槽ID、照射時間、匹数5を入力し、先頭10秒で検出枠・候補ID・反射の除外を確認する。
3. 実際の3分動画を解析し、検出されない個体、重なり、停止、線上の往復を目視で照合する。
4. 未確認・確認済み・除外と手動追加を試し、CSVの時刻・方向・合計・照射時間・修正前値を確認する。
5. 解析中と背景推定中に中断し、全時間完了扱いにならず、通常の再生操作へ戻ることを確認する。
6. 画面の回転、動画の変更、背景への移動、再解析、保存容量不足時の挙動を確認する。

## 実動画で必ず確認する項目

| 場面・条件 | 調べること |
| --- | --- |
| 5匹すべてが見える | 検出枠が各個体の全身を囲むか。尾の欠けで早く数えていないか |
| 中央線付近で停止・小さく往復 | 真の横断以外が増えないか。正しい往復は両方向に1回ずつか |
| 複数個体が重なる・離れる | 追跡切れやID入れ替わりが起きるか。不明区間が確認対象になるか |
| 気泡・器具・反射・水草 | 魚以外の候補が横断として出ないか。除外範囲に入る魚の見落としも調べる |
| 透明な体・暗い／明るい背景 | 検出を失わないか。魚が初期背景に取り込まれないか |
| 高速横断・被写体ブレ | サンプリング間に横断を見落とさないか。15枚/秒と比較する |
| 照射時間の異なる群 | 撮影時の映像の明るさ・反射の差で検出率が変わらないか。各群で評価する |
| 3分・30分の処理 | 実行時間、発熱、電池、ブラウザ停止、シーク失敗、保存容量、ピークメモリ |

Pixelの実メモリ・発熱、30分の実動画、実動画の検出精度、動画形式ごとの速度は**未確認**。まず720pまたは1080pのMP4（H.264）から始める。縮小解析でも元動画のデコード負荷は解像度に依存する。コーデックによって精密シークが遅い場合がある。

## 手動との比較で精度を評価する

- 各照射条件の同じ長さの区間で、候補一覧を見る前に独立に手動記録を作る。方向、全身横断の時刻、判断が不明な場面も記録する。
- 自動候補を確認・除外・修正する前の結果をCSVに保存する。手動修正後の一致率を自動検出の精度としない。
- 先に許容時間差（例：±0.3秒。動画とサンプリング間隔に合わせて事前に固定）を決め、同じ方向の時刻を1対1で照合する。複数の候補を同じ手動イベントに重複対応させない。
- 一致をTP、対応しない自動候補をFP、見落とした手動イベントをFNとして、適合率 `TP/(TP+FP)` と再現率 `TP/(TP+FN)` を計算する。分母0は算出不能とし、判断不能の区間は別に報告する。このイベント照合の自動計算は今回の画面にはない。
- 画面の比較機能は、独立手動の方向別件数との差と合計絶対誤差率のみ。FPとFNが相殺すると合計が一致しても精度は高くない。
- 群ごとに同じ設定・解像度・撮影時の照明・対象時間をそろえる。群によって検出率が変わる場合、未確認の候補数だけで光照射時間の効果を比較しない。
